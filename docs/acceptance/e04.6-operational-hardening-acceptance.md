## Scheduler remediation

Existing `scheduled_at`, `started_at`, `finished_at`, job, source, and status fields were
sufficient. Start delay and timing are derived deterministically, so **no schema migration was
required**.

Implemented behavior:

- execution timing is classified independently as `ON_TIME`, `LATE`, `MISSED`, `INTERRUPTED`, or
  `PENDING`;
- collector outcome remains independently `SUCCEEDED`, `PARTIAL`, `FAILED`, or scheduled;
- the boundary is explicit: delay `<= 300` seconds is on time and delay `> 300` is late;
- `scheduler status` and `scheduler verify-punctuality` are read-only and report
  `modified_records = 0`;
- manual ingestion runs cannot satisfy a scheduler window;
- historical scheduler timestamps and terminal outcomes are never rewritten;
- the Operations API and page expose continuity, punctuality, scheduled time, actual start, delay,
  timing, collector outcome, and next qualification window.

## arXiv cursor remediation

The incremental collector now reuses bounded date-window splitting when a query exceeds the real
volume threshold. It recursively divides only to the configured minimum partition, keeps request,
result, runtime, pacing, and retry limits, and persists child checkpoints so a restart resumes only
unfinished work. A parent cursor advances only after all children have durable Raw, Silver, and
Topic-match persistence. The collector never rewrites Registry queries or creates mappings.
